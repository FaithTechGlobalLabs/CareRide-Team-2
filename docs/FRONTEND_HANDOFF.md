# CareRide frontend handoff

Updated: October 3, 2026. Active branch: `Hail`.

## Current working path

The React app is in `react-web-careride/`. Its main staff-to-driver flow is implemented and browser-tested:

1. Staff logs in and books a free ride for a client.
2. An organization-approved driver sees and accepts the request.
3. The driver marks pickup and drop-off.
4. Staff sees the completed status and in-app notifications.

The frontend defaults to a browser-persisted screen demo when `VITE_API_URL` is unset. Set `VITE_API_URL` to the Express origin to use the PostgreSQL API instead.

## Important traps

- Clients are organization-managed records, not login accounts. Chong, Winnie, Joe, and Jamie appear in client and booking screens only.
- Demo data exists in two places and should stay aligned:
  - API seed: `backend/src/db/setup.ts`, applied with `npm run db:setup` after Postgres is running. See `docs/POSTGRES.md`.
  - Browser-only demo: `react-web-careride/src/features/careride/demo.ts`.
- The API ride status for a claimed trip is `approved`. The screen demo still uses `accepted` for that step. Pickup and no-show against the API start from `approved`.
- The browser demo storage key is `careride-screen-demo-v2`. Bump it when seed changes must replace users' existing local demo data.
- API list endpoints return wrappers such as `{ clients }` and `{ rides }`. `features/careride/api.ts` unwraps single-key responses.
- API driver login uses `user.kind = "driver"`, while frontend navigation uses `user.role`. `api.ts` normalizes this; do not remove that conversion.
- Driver eligibility needs all three seeded records: vehicle, active availability, and Belkin approval. Adding only a driver login will produce an empty available-rides screen.
- Round trips are two linked one-way rides. Each leg is claimed independently.
- `src/routeTree.gen.ts` is generated by the TanStack Router Vite plugin. Edit route files under `src/routes/`, not the generated tree.
- The frontend is responsive below 760px; the sidebar becomes bottom navigation. Check both mobile width and roughly 1440px after layout changes.
- Do not install or upgrade dependencies without explicit user approval. Existing verification commands require no new packages.
