CARERIDE · ENGINEERING OPTIONS

Your rides, in your calendar.

One iCalendar format can serve Apple Calendar and Google Calendar. The main choice is whether drivers download a snapshot, subscribe to an updating feed, or connect Google for faster updates.

QUICKEST FIRST STEP

Download .ics

Driver exports a date range and imports the file into their calendar.

Rough effort: 1–2 developer days

Required work

Export button, event serializer, driver filtering, timezone handling, and Apple/Google import checks. Can run entirely in this frontend.

Tradeoff

A snapshot stays as it was downloaded. Later changes and cancellations need manual correction.

RECOMMENDED FOR ONGOING USE

Subscribe to rides

Driver subscribes once to a personal CareRide feed; their calendar periodically fetches changes.

Rough effort: 3–5 developer days

Required work

Hosted HTTPS .ics endpoint, secret per-driver token, revoke/regenerate controls, stable event IDs, update and cancellation handling, setup instructions.

Tradeoff

Calendar providers control refresh timing. Do not promise instant updates or use the feed as the only urgent cancellation notice.

FASTER GOOGLE UPDATES

Connect Google

CareRide writes ride events into a dedicated Google calendar when the schedule changes.

Rough effort: 1–2 developer weeks

Required work

Google OAuth, protected refresh-token storage, event mapping, background jobs, retries, reconciliation, disconnect behavior, and production consent setup.

Tradeoff

More ongoing maintenance. This covers Google; Apple can still use the subscription feed. OAuth verification may add lead time.

These are preliminary implementation estimates, not commitments. The frontend was inspected; the separate production backend and deployment setup were not. Estimates include focused verification and exclude external approval delays.

Recommended event contract

  • Export the driver's assigned rides. Default to accepted/in-progress rides; optionally retain completed rides as history.
  • Use a stable ride ID per event and distinct IDs for outbound and return legs.
  • Show pickup time explicitly. Decide whether calendar blocks include the existing 15-minute buffer before and after the drive.
  • Use a consistent duration estimate. The calendar currently uses drive estimates or stored duration, with a 45-minute fallback.
  • Encode absolute timestamps correctly across Vancouver daylight-saving changes.
  • Use a generic title, time, and a CareRide link by default. Keep passenger details inside the authenticated app.

Backend responsibilities

  • Calendar services must be able to fetch the feed without the driver's browser login. Use a separate high-entropy, revocable feed token; never put the session bearer token in the URL.
  • Anyone holding the feed URL can retrieve its contents. Limit exported details and keep tokens out of logs.
  • Derive ownership on the server; never trust a driver ID supplied by the frontend.
  • Track event revisions and handle cancelled/reassigned rides. Verify client removal behavior rather than assuming missing events disappear.
  • For direct Google integration, use a dedicated CareRide calendar and the narrowest suitable scope; sync one way from CareRide.

Suggested sequence

Ship the .ics download first, reuse its event format for a subscription feed, then add direct Google integration only if delayed refresh is a real operational problem. Keep CareRide as the authoritative schedule.

What if “calendar data” includes availability?

Availability is separate from booked rides. CareRide already stores one-time, weekly, and monthly rules. Export those in a separate optional calendar using recurrence rules, timezone-aware local times, and start/end boundaries. Availability means the driver can accept a ride; it should not be confused with a booked commitment.

Verification checklist

Check import/subscription on Apple and Google, driver isolation, secret-token revocation, daylight-saving boundaries, missing durations, linked return rides, rescheduling, cancellation, reassignment, and duplicate-free updates. For Google API sync, also check retry recovery, expired consent, reconnects, and manual edits.
